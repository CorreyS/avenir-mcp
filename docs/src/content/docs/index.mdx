## Why avenir-mcp

<CardGrid>
  <Card title="Tools for tasks, not endpoints" icon="rocket">
    Classify a month of transactions, reconcile an account with the bank, forecast the
    balance, review a month: each is one tool, not ten API calls for the agent to chain.
  </Card>
  <Card title="Read-only by default" icon="seti:lock">
    The fourteen write tools are neither listed nor callable until you set
    `AVENIR_MCP_WRITE=1`. An agent cannot change what it cannot see.
  </Card>
  <Card title="Answers an agent can read" icon="document">
    Currency units, never milliunits. Typed output schemas with a description for every
    field, pagination, and errors that say what to fix.
  </Card>
  <Card title="Light on YNAB's quota" icon="seti:clock">
    A local copy of your transactions, refreshed by delta sync: most tools cost one or
    two of the 200 requests YNAB allows per hour.
  </Card>
  <Card title="Tracks YNAB's API" icon="approve-check-circle">
    Built and tested against the YNAB API version pinned in the repository. A weekly
    check compares it with the live specification, so a change at YNAB cannot pass
    unnoticed.
  </Card>
</CardGrid>

## Real answers, not prose

Tools return structured data the agent can rely on — and put into plain words for you.

> **You:** How did last month go?

The agent calls [`get_budget_vs_actual`](/avenir-mcp/reference/tools/get-budget-vs-actual/)
with `{"month": "2026-08-01"}` and gets, for every category, what was budgeted, what was spent and what is left. Here is
that answer on the demo plan, drawn:

<BudgetChart rows={august} when="lastMonth" />

> **Claude:** Last month stayed within budget everywhere: no category is overspent.
> The bills are paid, 207.49 is left for groceries and 58.00 for tennis, and the 200.00 set
> aside for holidays is untouched.
