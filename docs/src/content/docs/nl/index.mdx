## Waarom avenir-mcp

<CardGrid>
  <Card title="Hulpmiddelen voor taken, geen eindpunten" icon="rocket">
    Een maand aan transacties classificeren, een rekening afstemmen met de bank, het
    saldo voorspellen, een maand evalueren: elk daarvan is één hulpmiddel, niet tien API-aanroepen die de agent achter elkaar moet uitvoeren.
  </Card>
  <Card title="Standaard alleen-lezen" icon="seti:lock">
    De veertien schrijfhulpmiddelen worden pas weergegeven en kunnen pas worden aangeroepen nadat u de instellingen hebt geconfigureerd
    `AVENIR_MCP_WRITE=1`. Een agent kan niet wijzigen wat hij niet kan zien.
  </Card>
  <Card title="Antwoorden die een agent kan lezen" icon="document">
    Valuta-eenheden, nooit milli-eenheden. Getypeerde uitvoerschema’s met een beschrijving voor elk
    veld, paginering en foutmeldingen die aangeven wat er moet worden gecorrigeerd.
  </Card>
  <Card title="Geringe belasting van het YNAB-quotum" icon="seti:clock">
    Een lokale kopie van uw transacties, vernieuwd via delta-synchronisatie: de meeste tools kosten één of
    twee van de 200 verzoeken die YNAB per uur toestaat.
  </Card>
  <Card title="Volgt de API van YNAB" icon="approve-check-circle">
    Gebouwd en getest op basis van de YNAB-API-versie die in de repository is vastgelegd. Een wekelijkse
    controle vergelijkt deze met de actuele specificatie, zodat een wijziging bij YNAB niet
    onopgemerkt kan blijven.
  </Card>
</CardGrid>

## Echte antwoorden, geen proza

Deze tools leveren gestructureerde gegevens op waarop de medewerker kan vertrouwen — en die voor u in begrijpelijke taal worden uitgelegd.

> **Jij:** Hoe ging vorige maand?

De agent roept [`get_budget_vs_actual`](/avenir-mcp/nl/reference/tools/get-budget-vs-actual/)
aan met `{"month": "2026-08-01"}` en krijgt voor elke categorie wat er gebudgetteerd, wat er uitgegeven en wat er over is. Hier dat antwoord op het demoplan, als grafiek:
