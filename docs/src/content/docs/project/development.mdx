## Layout

<FileTree>

## Set up

```bash
git clone https://github.com/mathbeal/avenir-mcp && cd avenir-mcp
uv sync            # Python 3.14 and the locked dependencies
just check         # every gate CI runs
```

<Aside type="tip">
If the project sits in a folder synced by iCloud Drive, keep the virtual environment
outside it: `UV_PROJECT_ENVIRONMENT=~/.local/share/avenir-mcp/venv uv sync`. iCloud can
hide the `.pth` file of an editable install, which Python then ignores.
</Aside>

## The checks

`just check` runs, in CI's order:

| Check | Command | Fails when |
|---|---|---|
| format | `ruff format --check` | a file is not formatted |
| lint | `pylint` | the score is below 10.00; four or more computing lines repeated between two of the files it reads are enough to put it there (`duplicate-code`) |
| ruff | `ruff check` | a docstring of the package is not in Google style or leaves out an argument, the return value or an exception raised; imports are not sorted; bandit's security checks find a risky pattern (TLS not verified, a shell command, a password in the code…); the cyclomatic complexity of a function goes over 19, the worst the repository reaches today, a ceiling that only ever comes down (`C901`) |
| docstrings | `pydoclint` | a docstring of the package lists the arguments in another order than the signature, gives a type the annotation already gives, or is a bare summary for a function that takes arguments or returns a value |
| YNAB API terms | `pytest -m ynab_terms`, `python -m docsgen.terms` | a rule of YNAB's API terms is broken (naming, attribution word for word, YNAB's own image, a token for its owner only, the hourly limit), or YNAB changed its terms since the date checked; the README badge shows it |
| dead code | `vulture` | a name nothing else in the repository reads is neither registered by a decorator (`@mcp.tool`, `@pytest.fixture`…) nor listed, with the reason it is alive, in `vulture_whitelist.py` |
| dependencies | `deptry .` | the code imports a package `pyproject.toml` does not declare, or declares one it does not use |
| types | `mypy` (strict) | any type error |
| tests | `pytest` | a test fails, **any warning** is raised, or coverage of lines **or branches** is below 100 % |
| vocabulary | `lexdrift check avenir_mcp --baseline lexdrift.lock` | a new word appears for an idea already named |
| lock | `uv lock --check` | `uv.lock` does not match `pyproject.toml` |

CI also runs lychee on every link of the README and the documentation (`just links`,
and every Monday, since a page elsewhere can disappear), `typos`, `zizmor` on the workflows, `reuse lint` (every file states its copyright and licence), two builds of the wheel and the sdist that must be identical bit for bit (`just reproducible`), `pip-audit` on the locked dependencies,
`gitleaks` on every commit of the history (`just secrets`, with Docker),
the documentation build with the tests of its own code and `npm audit` on its dependencies, CodeQL and the OpenSSF Scorecard
(once the repository is public), a weekly comparison of YNAB's API with its snapshot
(`just api-drift`), a weekly mutation campaign (`just mutate`, below), and the official MCP Inspector
(`just inspect`), which checks the server as a client sees it on the demo plan: its
lists, the portability of its tool schemas, and one call of each kind. The test suite runs on Linux and macOS with Python 3.12,
3.13, 3.14 and 3.15, and on Windows with Python 3.14 (on a pull request, macOS tries the
newest Python only, 3.15: its runners cost ten Linux ones); coverage is enforced on Linux
and macOS, where the file-permission checks apply. On a pull request, every commit must be
signed off and the title must start with the kind of
change. Two checks must be green: **CI passed**, which stands for every job of the
quality workflow, and **MCP Inspector**, a workflow of its own so that its badge shows it
alone.

## Dependencies

[Renovate](https://docs.renovatebot.com) opens pull requests every Monday morning:

| Update | Handling |
|---|---|
| development tools, CI actions, the documentation site (minor and patch) | grouped, merged by itself once CI passes |
| `fastmcp`, `httpx`, `pydantic` — they run in front of users' plans | one pull request each, reviewed by hand; the evaluation runs before a `fastmcp` update |
| any major version | one pull request each, reviewed by hand |
| the weekly refresh of the lock file | one pull request, reviewed by hand |
| a known vulnerability | at once, whatever the day |

A new release waits seven days before Renovate proposes it, so a broken or malicious
version withdrawn quickly never reaches the project. For now, during early development,
the weekly refresh of the lock file is exempt.

## Tests

| Kind | Files | What they check |
|---|---|---|
| Unit | `test_classifier`, `test_triage`, `test_writes`, `test_reconcile`, `test_forecast`, `test_analytics`, `test_journal`, `test_client` | the pure logic and the HTTP client, with invented data |
| Properties | `test_properties` | with Hypothesis, rules that hold for any input: amounts round-trip, spreading keeps every cent, months add up, cursors, bank text, confirmation fingerprints |
| Protocol | `test_protocol*`, `test_context`, `test_policy` | tools through an in-memory MCP client: schemas, annotations, confirmation paths, undo |
| Documentation | `test_docs` | generated pages and examples match the code; every page exists in each translation; every environment variable is documented |
| API coverage | `test_api_coverage` | every operation of YNAB's API is used by a tool, planned or left out with a reason; the client calls only documented paths |
| Hygiene | `test_hygiene` | no IBAN, token, statement, home path or Finder copy in the repository |
| Evaluation | `test_evals` | the evaluation's own checks are right |

Tests are written first. No test calls YNAB.

`just mutate` runs mutation testing (mutmut) on the modules that compute: it changes the
code on purpose, some 4,500 times, and checks that a test fails each time. A change no
test notices is a line whose decision nothing reads: the answer is the missing test, or
the mark `# pragma: no mutate` on a one-line statement, with the reason that change can
alter no answer. Today every mutant is noticed.

What is measured is the pure logic. `do_not_mutate` in `pyproject.toml` leaves out the
modules that talk to YNAB, to the transport or to the disk — the client, the server and
its tool modules, the journal, the logs, the HTTP authentication, the confirmation, the
application — and those holding only annotations and constants: their tests are the
protocol and client tests, slow to run against every mutant, and they check how the
pieces are wired together rather than what a line decides. Only the files listed in
`pytest_add_cli_args_test_selection` run against a mutant, so each measured module has to
be covered by one of them: a module no listed file reaches comes back "no tests", which
measures nothing.

The `mutation` workflow runs the campaign every Monday, on two cores in some eight
minutes, and fails when a mutant survives, when one runs no test, or when the campaign
finds no mutant at all — a configuration that measures nothing would pass otherwise. Its
badge in the README shows that single run: a surviving mutant leaves it red for the week,
until the next Monday or a run started by hand. A mutant that makes a test loop for ever
instead of failing does not: the test did notice it, and mutmut counts it apart, as a
timeout.

`just bench` times the modules that compute on a generated five-year plan, about 9,000
transactions (pytest-benchmark). On a laptop the slowest, preparing a page of suggestions,
takes about 30 ms: a tool's time is spent waiting for YNAB, not computing.

`just fuzz` runs the Hypothesis properties with 50,000 examples each instead of 100 (a few
minutes; `just fuzz 200000` for longer), on what comes from outside: bank labels, damaged
journals, HTTP headers, amounts, cursors. A failure is saved and replayed, minimised, by
the next run. CI does it every night with 200,000. The first run found a journal byte that
was not text (0x80) surfacing as a bare codec error instead of the line to fix.

`just complexity` lists the functions radon ranks C or worse, cyclomatic complexity 11 and
above, the worst of each file first, then the average over every block, counting the ones
not shown. It also prints the maintainability index of every module of the package, lowest
first: one number aggregating Halstead volume, cyclomatic complexity and line count, which
ranks the files against each other and shows where each is heading rather than returning a
verdict, since radon's A rank starts at 20 and every file of the package is far above it.
A report to read, not a gate: it never fails, and CI does not run it. Its version is pinned
and `uvx` fetches it, as for pydoclint. The complexity it prints is not the complexity
`C901` limits: radon counts boolean operators, conditional expressions and comprehensions,
which ruff's mccabe leaves out, so the same function scores higher here than it does against
the limit.

## Documentation

```bash
uv run python -m docsgen   # tool pages, error catalogue, examples
just docs                  # build the site in every language; broken links fail
just docs-serve            # live preview on http://localhost:4321/avenir-mcp/
```

`docsgen` runs avenir-mcp on the demo plan and writes what it really answers, with the
date fixed and random ids replaced. Hand-written pages exist in English, French,
Spanish, German and Dutch; a test fails when one is missing.

### Hosting

The site lives on Cloudflare Pages (`avenir-mcp.pages.dev`), which builds it from the
repository with `npm run build:cloudflare` and serves it under `/avenir-mcp/`; the root
redirects there. GitHub Pages, which cannot send security headers, only redirects old
links: the `docs` workflow publishes there, for every page of the site, a page that sends
the reader to the same address on Cloudflare, and a 404 page that does the same for any
other path. Cloudflare Pages sends the headers of `docs/cloudflare/_headers` with every
file: a Content-Security-Policy, HSTS, `X-Content-Type-Options: nosniff`,
`X-Frame-Options: DENY`, a referrer policy, a permissions policy and an opener policy.
The policy allows the site's own files and each inline script and style of the built
pages by its SHA-256, computed at build time; `'wasm-unsafe-eval'` lets the search run
its WebAssembly, and style attributes are allowed through `style-src-attr` only. The build
fails, in CI too, when a required header is missing or weakened. The `DOCS_SITE`
environment variable sets the address used in canonical links and the sitemap.

## Commits and releases

- Commit messages start with a type — `feat:`, `fix:`, `docs:`, `refactor:`, `test:`,
  `build:`, `ci:`, `chore:` — because `CHANGELOG.md` is generated from them by
  git-cliff.
- To release: `just changelog`, commit, tag `vX.Y.Z` matching `avenir_mcp.__version__`,
  and publish a GitHub release. The `publish` workflow builds twice with the tagged commit's date, stops unless both builds agree, runs `twine check
  --strict` and uploads to PyPI through Trusted Publishing: no token is stored.
- Then the MCP registry: `server.json` carries the same version (a test checks it); run
  `mcp-publisher login github`, then `mcp-publisher publish`. PyPI ownership is proven by the
  `mcp-name:` line of the README.
- The Claude Desktop extension carries it too: `mcpb/manifest.json` and the
  `avenir-mcp==` pin of `mcpb/pyproject.toml` move with `avenir_mcp.__version__` (a test
  checks both), or the extension installs the release before it.
- Then the Claude Code plugin, once PyPI has the release: raise the version in
  `plugin/.claude-plugin/plugin.json` and the pin in `plugin/pyproject.toml`, run
  `uv lock --project plugin`, and commit `plugin/uv.lock`. The three name one release, and
  a test fails while they disagree. `uv lock` resolves only a release PyPI already serves,
  so this is the commit that follows the publication rather than a part of it.
