avenir-mcp donne à un agent 37 outils, 4 ressources et 4 prompts sur vos plans YNAB. Cette
page les classe selon ce que vous voulez faire. Chaque ligne donne une phrase à dire à
l'agent ; c'est lui qui choisit l'outil.

<Aside type="note">
**L** = lecture seule, toujours disponible. **É** = écriture, disponible avec
`AVENIR_MCP_WRITE=1`, prévisualisée et confirmée. **↺** = annulable avec
`undo_operation`.
</Aside>

<Aside type="tip" title="Plan ou budget ?">
Le [journal des modifications de l'API de YNAB](https://api.ynab.com/#changelog) indique que
la version 1.79.0, publiée le 05/03/2026, a renommé `/budgets` en `/plans`, tout comme les
outils d'avenir-mcp
(`list_plans`, `plan_id`). Dites le mot que vous préférez : l'agent comprend les deux et
vous répond avec le vôtre. « Mon budget restaurants » désigne toujours le montant attribué
à cette catégorie.
</Aside>

## Classer les transactions

| Vous dites | Outil | |
|---|---|---|
| *« Récupère les dernières transactions de ma banque. »* | [`import_transactions`](/avenir-mcp/fr/reference/tools/import-transactions/) — ce que fait Import dans YNAB, appliqué aussitôt | É |
| *« Qu'est-ce qui attend une catégorie ? »* | [`suggest_categories`](/avenir-mcp/fr/reference/tools/suggest-categories/) — transactions en attente, avec une proposition quand votre historique est clair | L |
| *« Oui, applique. »* | [`apply_categories`](/avenir-mcp/fr/reference/tools/apply-categories/) — un lot confirmé | É ↺ |
| *« Mets un drapeau sur celles que je dois vérifier dans YNAB. »* | [`flag_transactions`](/avenir-mcp/fr/reference/tools/flag-transactions/) — un drapeau de couleur, à regarder dans YNAB | É ↺ |
| *« Quels bénéficiaires ne sont que des libellés bancaires ? »* | [`list_payees`](/avenir-mcp/fr/reference/tools/list-payees/) — chaque bénéficiaire avec le commerçant auquel son libellé se normalise, et sa fréquence d'usage | L |
| *« Appelle celui-là Market Fresh. »* | [`rename_payee`](/avenir-mcp/fr/reference/tools/rename-payee/) — un libellé devient le nom du commerçant, pour tout son historique | É ↺ |
| *« Ventile ce ticket : 81,15 en courses, 5,25 en entretien. »* | [`split_transaction`](/avenir-mcp/fr/reference/tools/split-transaction/) — une transaction sur plusieurs catégories ; s'annule dans YNAB, pas ici | É |
| *« Marque-les comme revues. »* | [`approve_transactions`](/avenir-mcp/fr/reference/tools/approve-transactions/) — lève le marqueur *unapproved* de YNAB | É |

Les propositions reconnaissent un commerçant à travers ses libellés bancaires
(`CB MARKET FRESH FACT 050926 525130******1` et `… 190926 …` sont la même boutique),
apprennent séparément les entrées et les sorties d'argent, et ne proposent jamais de
catégorie masquée. Guide :
[Classer les transactions en attente](/avenir-mcp/fr/guides/classify/). Fonctionnement :
[Suggestions](/avenir-mcp/fr/concepts/suggestions/).

| Vous dites | Outil | |
|---|---|---|
| *« Ma banque affiche 3 440,80. YNAB est-il d'accord ? »* | [`reconcile_account`](/avenir-mcp/fr/reference/tools/reconcile-account/) — explique un écart sans rien écrire ; rapproche une fois d'accord | É ↺ |

[Ajouter des transactions manquantes](/avenir-mcp/fr/guides/missing-transactions/).

## Procédures toutes prêtes

Quatre [prompts](/avenir-mcp/fr/reference/resources-and-prompts/#prompts) guident
l'agent dans une tâche complète. Dans Claude Code, ce sont des commandes slash du serveur
`avenir-mcp`.

| Prompt | Arguments | Ce qu'il fait |
|---|---|---|
| `classify_pending` | plan | propositions, vos choix, un lot confirmé, l'identifiant pour annuler |
| `monthly_review` | plan, mois | les totaux, ce qui ressort, les corrections proposées |
| `reconcile` | plan, compte, solde bancaire | l'écart expliqué, puis un rapprochement confirmé |
| `plan_next_month` | plan | projection et hypothèses, puis les montants du mois suivant |

## Intégré

- **Sécurité :** lecture seule par défaut, confirmation liée à l'aperçu exact, journal
  local pour annuler, texte bancaire traité comme non fiable. Voir
  [Sécurité par conception](/avenir-mcp/fr/concepts/safety/).
- **Économie :** une copie locale des transactions mise à jour par synchronisation
  incrémentale ; la plupart des outils coûtent une ou deux requêtes YNAB. Voir
  [Données et synchronisation](/avenir-mcp/fr/concepts/data-and-sync/).
- **Clarté pour les agents :** unités monétaires, schémas de sortie typés avec une
  description par champ, pagination, [erreurs](/avenir-mcp/fr/reference/errors/)
  exploitables.
- **Protocole :** MCP 2026-07-28 et versions antérieures ; stdio ou HTTP streamable.
