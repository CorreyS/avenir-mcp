## Warum avenir-mcp

<CardGrid>
  <Card title="Tools für Aufgaben, nicht für Endpunkte" icon="rocket">
    Einen Monat Transaktionen kategorisieren, ein Konto mit der Bank abgleichen, den
    Kontostand vorausberechnen, einen Monat auswerten: Jede Aufgabe ist ein Tool,
    nicht zehn API-Aufrufe, die der Agent verketten muss.
  </Card>
  <Card title="Standardmäßig nur lesend" icon="seti:lock">
    Die vierzehn schreibenden Tools sind weder aufgelistet noch aufrufbar, bis Sie
    `AVENIR_MCP_WRITE=1` setzen. Ein Agent kann nicht ändern, was er nicht sieht.
  </Card>
  <Card title="Antworten, die ein Agent lesen kann" icon="document">
    Währungseinheiten, niemals Milliunits. Typisierte Ausgabeschemas mit einer
    Beschreibung für jedes Feld, Paginierung und Fehler, die sagen, was zu
    korrigieren ist.
  </Card>
  <Card title="Schont das YNAB-Kontingent" icon="seti:clock">
    Eine lokale Kopie Ihrer Transaktionen, per Delta-Synchronisation aktualisiert: Die
    meisten Tools kosten eine oder zwei der 200 Anfragen, die YNAB pro Stunde erlaubt.
  </Card>
  <Card title="Folgt der YNAB-API" icon="approve-check-circle">
    Gebaut und getestet gegen die im Repository festgelegte Version der YNAB-API. Eine
    wöchentliche Prüfung vergleicht sie mit der Live-Spezifikation, damit eine Änderung
    bei YNAB nicht unbemerkt bleibt.
  </Card>
</CardGrid>

## Echte Antworten, keine Prosa

Die Tools liefern strukturierte Daten, auf die sich der Agent verlassen kann – und
die er Ihnen in klare Worte fasst.

> **Sie:** Wie lief der letzte Monat?

Der Agent ruft [`get_budget_vs_actual`](/avenir-mcp/de/reference/tools/get-budget-vs-actual/)
mit `{"month": "2026-08-01"}` auf und erhält für jede Kategorie, was budgetiert, was ausgegeben wurde und was übrig ist. Hier diese Antwort auf dem Demo-Plan, als Grafik:
