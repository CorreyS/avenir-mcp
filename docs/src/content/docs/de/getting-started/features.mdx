avenir-mcp gibt einem Agenten 33 Tools, 4 Ressourcen und 4 Prompts für Ihre
YNAB-Plans. Diese Seite ordnet sie nach dem, was Sie tun möchten. Jede Zeile nennt einen
Satz, den Sie dem Agenten sagen können; der Agent wählt das Tool.

<Aside type="note">
**L** = nur lesend, immer verfügbar. **S** = schreibend, verfügbar mit
`AVENIR_MCP_WRITE=1`, als Vorschau gezeigt und bestätigt. **↺** = mit `undo_operation`
rückgängig zu machen.
</Aside>

<Aside type="tip" title="Plan oder Budget?">
Im [API-Änderungsprotokoll](https://api.ynab.com/#changelog) von YNAB ist vermerkt, dass in
der am 05.03.2026 veröffentlichten Version 1.79.0 `/budgets` in `/plans` umbenannt wurde;
dies gilt auch für die Tools von avenir-mcp (`list_plans`,
`plan_id`). Sagen Sie, was Ihnen lieber ist: Der Agent versteht beides und antwortet mit
Ihrem Wort. „Mein Budget für Restaurants“ meint weiterhin den Betrag, der dieser Kategorie
zugewiesen ist.
</Aside>

## Transaktionen kategorisieren

| Sie sagen | Tool | |
|---|---|---|
| *„Hol die neuesten Transaktionen meiner Bank.“* | [`import_transactions`](/avenir-mcp/de/reference/tools/import-transactions/) – was Import in YNAB tut, sofort angewendet | S |
| *„Was braucht noch eine Kategorie?“* | [`suggest_categories`](/avenir-mcp/de/reference/tools/suggest-categories/) – ausstehende Transaktionen, mit Vorschlag, wenn Ihre Historie eindeutig ist | L |

| *„Markiere die Buchungen, die ich in YNAB prüfen sollte.“* | [`flag_transactions`](/avenir-mcp/de/reference/tools/flag-transactions/) – eine farbige Markierung, in YNAB anzusehen | S ↺ |
| *„Welche Zahlungsempfänger sind nur Bankbeleg-Texte?“* | [`list_payees`](/avenir-mcp/de/reference/tools/list-payees/) – jeder Zahlungsempfänger mit dem Händler, auf den sein Text normalisiert wird, und wie oft er genutzt wird | L |
| *„Nenne den Market Fresh.“* | [`rename_payee`](/avenir-mcp/de/reference/tools/rename-payee/) – ein Text wird zum Namen des Händlers, für seine ganze Geschichte | S ↺ |
| *„Teile diesen Beleg auf: 81,15 Lebensmittel, 5,25 Haushalt.“* | [`split_transaction`](/avenir-mcp/de/reference/tools/split-transaction/) – eine Transaktion auf mehrere Kategorien; in YNAB rückgängig zu machen, nicht hier | S |
| *„Markiere sie als geprüft.“* | [`approve_transactions`](/avenir-mcp/de/reference/tools/approve-transactions/) – entfernt YNABs Kennzeichen *unapproved* | S |

Vorschläge erkennen einen Händler über seine Bankbezeichnungen hinweg
(`CB MARKET FRESH FACT 050926 525130******1` und `… 190926 …` sind derselbe Laden), lernen
Ein- und Ausgänge getrennt und verweisen nie auf eine ausgeblendete Kategorie. Anleitung:
[Ausstehende Transaktionen kategorisieren](/avenir-mcp/de/guides/classify/). Wie es
funktioniert: [Vorschläge](/avenir-mcp/de/concepts/suggestions/).

## Mit der Bank vergleichen

| Sie sagen | Tool | |
|---|---|---|
| *„Meine Bank zeigt 3.440,80. Stimmt YNAB damit überein?“* | [`reconcile_account`](/avenir-mcp/de/reference/tools/reconcile-account/) – erklärt eine Differenz, ohne zu schreiben; gleicht ab, sobald es passt | S ↺ |
| *„Füge die Apothekenzahlung hinzu, die der Import verpasst hat.“* | [`create_transactions`](/avenir-mcp/de/reference/tools/create-transactions/) | S ↺ |

Eine Differenz wird erklärt durch ausstehende Transaktionen, diejenige, deren Betrag der
Differenz entspricht, und wahrscheinliche Duplikate (gleicher Betrag und Händler, höchstens
3 Tage auseinander). Anleitungen: [Ein Konto abgleichen](/avenir-mcp/de/guides/reconcile/),
[Fehlende Transaktionen ergänzen](/avenir-mcp/de/guides/missing-transactions/).

## Fertige Abläufe

Vier [Prompts](/avenir-mcp/de/reference/resources-and-prompts/#prompts) führen den Agenten
durch eine ganze Aufgabe. In Claude Code sind es Slash-Befehle des Servers `avenir-mcp`.

| Prompt | Argumente | Was er tut |
|---|---|---|
| `classify_pending` | Plan | Vorschläge, Ihre Entscheidungen, ein bestätigter Stapel, die ID zum Rückgängigmachen |
| `monthly_review` | Plan, Monat | Summen, was auffällt, vorgeschlagene Korrekturen |
| `reconcile` | Plan, Konto, Kontostand der Bank | die Differenz erklärt, dann ein bestätigter Abgleich |
| `plan_next_month` | Plan | Prognose und Annahmen, dann die Beträge des nächsten Monats |

## Eingebaut

- **Sicherheit:** standardmäßig nur lesend, Bestätigung an die genaue Vorschau gebunden,
  ein lokales Journal zum Rückgängigmachen, Banktexte als nicht vertrauenswürdig
  behandelt. Siehe [Sicherheit durch Design](/avenir-mcp/de/concepts/safety/).
- **Sparsamkeit:** eine lokale Kopie Ihrer Transaktionen, per Delta-Synchronisation
  aktualisiert; die meisten Tools kosten eine oder zwei YNAB-Anfragen. Siehe
  [Daten und Synchronisation](/avenir-mcp/de/concepts/data-and-sync/).
- **Klarheit für Agenten:** Währungseinheiten, typisierte Ausgabeschemas mit einer
  Beschreibung je Feld, Paginierung, [Fehler](/avenir-mcp/de/reference/errors/), die sagen,
  was zu tun ist.
- **Protokoll:** MCP 2026-07-28 und frühere Versionen; stdio oder Streamable HTTP.
