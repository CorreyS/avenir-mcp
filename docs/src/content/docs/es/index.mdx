## Por qué avenir-mcp

<CardGrid>
  <Card title="Herramientas para tareas, no para endpoints" icon="rocket">
    Clasificar un mes de transacciones, conciliar una cuenta con el banco, prever el
    saldo, revisar un mes: cada tarea es una herramienta, no diez llamadas a la API que
    el agente deba encadenar.
  </Card>
  <Card title="Solo lectura por defecto" icon="seti:lock">
    Las catorce herramientas de escritura no se listan ni se pueden llamar hasta que defina
    `AVENIR_MCP_WRITE=1`. Un agente no puede cambiar lo que no ve.
  </Card>
  <Card title="Respuestas que un agente puede leer" icon="document">
    Unidades monetarias, nunca miliunidades. Esquemas de salida tipados con una
    descripción por campo, paginación, y errores que dicen qué corregir.
  </Card>
  <Card title="Ligero con la cuota de YNAB" icon="seti:clock">
    Una copia local de sus transacciones, actualizada por sincronización incremental: la
    mayoría de las herramientas cuestan una o dos de las 200 peticiones por hora de YNAB.
  </Card>
  <Card title="Sigue la API de YNAB" icon="approve-check-circle">
    Construido y probado contra la versión de la API de YNAB fijada en el repositorio.
    Una comprobación semanal la compara con la especificación en vivo, para que un cambio
    en YNAB no pase inadvertido.
  </Card>
</CardGrid>

## Respuestas estructuradas, no prosa

Las herramientas devuelven datos estructurados en los que el agente puede confiar — y
que este le explica con palabras sencillas.

> **Usted:** ¿Cómo fue el mes pasado?

El agente llama a [`get_budget_vs_actual`](/avenir-mcp/es/reference/tools/get-budget-vs-actual/)
con `{"month": "2026-08-01"}` y recibe, para cada categoría, lo presupuestado, lo gastado y lo que queda. Esta es esa respuesta sobre el plan de demostración, en forma de gráfico:
